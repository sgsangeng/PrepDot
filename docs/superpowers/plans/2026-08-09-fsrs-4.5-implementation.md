## Day 1：搞懂算法 + 写出纯函数核心（不碰 Spring/数据库）

### Task 1: 概念预习 + 手算一个例子

这一步不写代码，目的是在动手写公式之前，先靠一个可以手算验证的小例子建立数字直觉——不然直接看一堆 `w[8]`、`exp`、`pow` 的公式会很抽象。

**背景（对照设计文档 2.1-2.6 节）：**

FSRS 用三个数描述一张卡片的记忆状态：
- **D（难度）**：1-10，这张卡对你来说有多难
- **S（稳定性）**：单位是"天"，定义为"记忆概率掉到 90% 需要多少天"
- **R（可提取性）**：0-1 的概率，当前这一刻你还记得的概率，是 S 和"过了几天没复习"的函数，不存数据库，随用随算

**公式（17 个默认权重 `w[0]..w[16]`）：**

```
默认权重: [0.4872, 1.4003, 3.7145, 13.8206, 5.1618, 1.2298, 0.8975, 0.031,
           1.6474, 0.1367, 1.0461, 2.1072, 0.0793, 0.3246, 1.587, 0.2272, 2.8755]

可提取性:  R(t, S) = (1 + FACTOR·t/S) ^ DECAY      DECAY=-0.5, FACTOR=19/81
下次间隔:  I(S)    = (S/FACTOR) · (0.9^(1/DECAY) - 1)     【目标保留率固定 0.9】

首次评分 G∈{1=again,2=hard,3=good,4=easy}:
  S0(G) = w[G-1]
  D0(G) = w[4] - (G-3)·w[5]

后续复习（已经复习过至少一次）:
  难度更新: D' = w[7]·w[4] + (1-w[7])·(D - w[6]·(G-3))，裁剪到 [1,10]
  评分不是 again（记住了）:
    S' = S · ( e^w[8] · (11-D) · S^-w[9] · (e^(w[10]·(1-R)) - 1) · [w[15] 如果 G=hard] · [w[16] 如果 G=easy] + 1 )
  评分是 again（忘了）:
    S' = w[11] · D^-w[12] · ((S+1)^w[13] - 1) · e^(w[14]·(1-R))
```

**手算练习（不用编译器，用计算器）：** 算出"第一次复习评分 good（G=3）"时的初始状态：

```
S0(3) = w[2] = 3.7145
D0(3) = w[4] - (3-3)·w[5] = w[4] - 0 = 5.1618
```

再算"按目标保留率 90% 反推的下次间隔"：

```
I(3.7145) = (3.7145 / (19/81)) · (0.9^(1/-0.5) - 1)
          = (3.7145 / 0.234568) · (0.9^-2 - 1)
          = 15.8371 · (1.234568 - 1)
          = 15.8371 · 0.234568
          ≈ 3.7145
```

**关键发现（记住这个，后面写单测会用到）：** 当目标保留率恰好是 0.9 时，`I(S) == S`——因为 FSRS 的稳定性定义本身就是"降到 90% 需要的天数"，这不是巧合，是公式自洽的必然结果。这个等式后面会直接拿来当单元测试，不用怕算错。

**自检：** 能不能不看上面的推导，自己口头解释一遍"为什么 `I(0.9, S) = S` 这个等式一定成立"？能解释清楚再往下走。

```java
package com.prepdot.algorithm;

import org.springframework.stereotype.Component;

@Component
public class FsrsScheduler {

    private static final double[] DEFAULT_WEIGHTS = {
            0.4872, 1.4003, 3.7145, 13.8206, 5.1618, 1.2298, 0.8975, 0.031,
            1.6474, 0.1367, 1.0461, 2.1072, 0.0793, 0.3246, 1.587, 0.2272, 2.8755
    };
    private static final double DECAY = -0.5;
    private static final double FACTOR = 19.0 / 81.0;
    private static final double TARGET_RETENTION = 0.9;

    private final double[] w;

    public FsrsScheduler() {
        this(DEFAULT_WEIGHTS);
    }

    public FsrsScheduler(double[] weights) {
        if (weights.length != 17) {
            throw new IllegalArgumentException("FSRS-4.5 需要 17 个权重参数，实际收到 " + weights.length + " 个");
        }
        this.w = weights;
    }

    public double retrievability(double stability, double elapsedDays) {
        if (elapsedDays <= 0) {
            return 1.0;
        }
        return Math.pow(1 + FACTOR * elapsedDays / stability, DECAY);
    }
}
```

`@Component` 是为了后面 Day 2 能被 Spring 注入进 `PlanServiceImpl`；测试里用 `new FsrsScheduler()` 直接实例化完全没问题，两种用法互不影响。

```java
public FsrsState initialState(int rating) {
```

```java
public FsrsState reviewExisting(FsrsState state, int rating, double elapsedDays) {
    double r = retrievability(state.stability(), elapsedDays);
    double newDifficulty = clipDifficulty(
            w[7] * w[4] + (1 - w[7]) * (state.difficulty() - w[6] * (rating - 3))
    );
    double newStability = (rating == 1)
            ? forgetStability(state.difficulty(), state.stability(), r)
            : successStability(state.difficulty(), state.stability(), r, rating);
    return new FsrsState(newDifficulty, newStability);
}

private double successStability(double difficulty, double stability, double r, int rating) {
    double hardPenalty = (rating == 2) ? w[15] : 1.0;
    double easyBonus = (rating == 4) ? w[16] : 1.0;
    double increase = Math.exp(w[8])
            * (11 - difficulty)
            * Math.pow(stability, -w[9])
            * (Math.exp(w[10] * (1 - r)) - 1)
            * hardPenalty
            * easyBonus
            + 1;
    return stability * increase;
}

private double forgetStability(double difficulty, double stability, double r) {
    return w[11]
            * Math.pow(difficulty, -w[12])
            * (Math.pow(stability + 1, w[13]) - 1)
            * Math.exp(w[14] * (1 - r));
}
```

```java
     * （卡片还没被 FSRS 初始化过）时，直接返回 fallback，不做计算。

    public int currentMemoryScore(Double difficulty, Double stability,
                                   java.time.LocalDateTime lastReviewedAt, int fallback) {
        if (difficulty == null || stability == null || lastReviewedAt == null) {
```

```markdown
# FSRS 面试话术小结

## 一句话
把简历项目原来"复习对了加分、错了扣分"的固定规则，换成了 Anki 现在默认用的 FSRS-4.5 间隔重复算法——用 Difficulty/Stability/Retrievability 三个量对每张卡片单独建模，而不是所有卡片共用一套固定加减分规则。

## 为什么不是自己发明的算法，也不是直接抄 SM-2
FSRS 是 open-spaced-repetition 团队拿几亿条 Anki 真实复习记录做 MLE 训出来的公开算法，比 SM-2 的核心区别是：SM-2 只有一个会随时间漂移的 ease factor 标量，FSRS 把"多久没复习会忘"显式建模成一个连续的幂函数遗忘曲线，可以直接按目标记忆概率反推间隔。

## 我具体做了什么（不是只调了个库）
手写了公式的 Java 实现（不是直接 `implementation 'fsrs:xxx'` 引入现成库），包括初始状态、难度均值回归更新、成功/遗忘两套稳定性更新公式，并且用 TDD 方式开发——尤其是稳定性更新公式带 `exp`/`pow`，手算验证风险高，所以测试用的是不变量断言（比如"成功复习后稳定性绝不会下降""难度必须裁剪在 [1,10]"）加 golden master 回归测试，而不是死记硬背几个数字。

## 有意识没做的部分（体现边界感，别不懂装懂）
- 没做个性化参数优化（FSRS 官方设计允许按用户历史拟合专属权重，用的是全局默认权重）
- 没做知识图谱增强（卡片之间的记忆传播，官方 FSRS 也不做这个，是我们这边如果继续做才会有的差异化方向）
- 目标保留率写死 90%，没做成用户可调参数
这三个都是刻意的范围控制，不是能力不够——如果面试官追问，可以直接讲这是"先把公开发表、可验证的核心落地对，再谈差异化"的工程判断。
```
